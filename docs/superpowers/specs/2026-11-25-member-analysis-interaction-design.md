# 成员分析与成员交互设计规格

- 日期：2026-11-25
- 状态：待用户审阅
- 范围：官网团队页、成员档案页、公开成员关系探索
- 已确认方向：A+C（发现协作者 + 个人能力展示），采用“成员探索与独立档案页 + 目录旁协作图”

## 1. 背景与现状

官网现有 `TeamPage`、`MemberCard` 和 `MemberTechDetail`，支持四类成员卡片、部分技能与项目展示、成员详情弹窗和 Gitee / GitHub 贡献概览。成员元数据位于 `src/lib/i18n/constants/team.ts`，中文文案位于 `src/lib/i18n/locales/zh.ts`，英文版直接复用成员常量；技术方向匹配逻辑目前封装在成员详情弹窗中。

当前缺口：

- 团队页只能按角色筛选，无法按技能、项目或关键词发现成员。
- 个人详情依赖弹窗，没有可分享的独立链接。
- 技术方向和关系信息只服务于个人详情，无法帮助成员发现跨组协作者。
- 贡献快照更新于 2026-07-06，不能与“当前活跃度”或实时互动混为一谈。
- 成员数据存在同名记录：维护者与贡献者中都有“张旺旺”。即使两条记录使用同一个 GitHub 链接，本次也不能仅凭姓名或链接自动认定二者为同一真实身份。

## 2. 目标

1. 让访客能通过姓名、角色、技能或项目找到成员。
2. 让每位公开成员拥有稳定、可分享的个人档案链接。
3. 用可验证的共同项目与共同技能，帮助成员发现潜在协作者。
4. 补充技术方向覆盖、项目参与分布和资料完整度分析。
5. 复用现有静态数据与联系方式，不引入新的账户、后端或消息系统。

## 3. 非目标

- 不实现站内私信、即时聊天、在线状态、评论或自动发送邀请。
- 不根据标签生成合作成功率、成员能力排名或综合分数。
- 不把贡献提交数作为成员活跃度或价值的唯一依据。
- 不自动合并同名成员、GitHub / Gitee 身份或 Git 提交身份。
- 不新增关系数据库、用户登录或第三方图谱库。
- 本次不生成每位成员的静态 SEO 快照，也不承诺社交平台的个人专属抓取卡片；首版通过客户端更新档案页标题与描述。
- 不重构赞助商、合照画廊或贡献统计同步脚本。

## 4. 用户路径

### 4.1 发现与了解成员

1. 访客打开 `/team`。
2. 在成员探索区输入姓名、角色、简介、技能或项目名称，并可选择成员类别。
3. 左侧成员列表实时更新，显示匹配数量和清空筛选入口。
4. 点击成员卡片或卡片中的“查看档案”进入 `/team/member/:memberId`。
5. 在档案页查看自述技能、技术方向、参与项目和真实公开联系入口。

### 4.2 通过关系图发现协作者

1. 在目录右侧的协作面板选择“项目”或“技术方向”。
2. 选择具体项目或方向，图形显示与该节点直接关联的公开成员。
3. 点击成员节点打开对应档案；通过下拉选择器切换项目或方向。
4. 关联选择同步缩小成员列表范围，并用可移除的筛选标签说明当前范围。
5. 档案页中的“直接协作者”列出与当前成员至少有一个共同项目或共同技术方向的成员，显示具体依据。

### 4.3 发起交流

1. 访客在档案页复制链接或一段本地生成的协作邀约文本。
2. 系统只执行复制并展示成功状态，不自动发送任何内容。
3. 访客通过成员已公开的 GitHub、Gitee、Bonjour、LinkedIn 或邮箱主动建立联系。
4. 没有公开联系方式的成员显示“暂未公开联系方式”，不伪造联系按钮。

## 5. 页面与交互设计

### 5.1 团队页成员探索区

保留现有团队介绍、成员滚动条、贡献统计、合照与赞助商区块。现有角色筛选升级为探索工具栏，包含：

- 搜索输入框，支持中文、英文及大小写不敏感匹配。
- 现有四类成员筛选和“全部”。
- 当前关系范围标签与清除按钮。
- 匹配成员计数和无结果说明。

桌面端采用两列布局：左侧为成员目录，右侧为可随视口滚动的协作面板。两列保持合理宽度，成员卡片的图片、姓名和主要角色优先，不让关系图压缩目录至不可用。

移动端协作面板改为折叠区域，始终以“相关成员”可访问列表展示与桌面图形相同的关系信息，不渲染 SVG。搜索与筛选在移动端保持可用，不使用悬停作为唯一操作方式。

成员卡片增加明确的档案链接；卡片空白区域也可通过键盘聚焦并打开档案。GitHub、Gitee、邮箱和项目链接继续作为独立链接，点击它们不触发档案跳转。

### 5.2 成员档案页

新增 `/team/member/:memberId`，在 `/team` 路由之前注册。档案页沿用网站 Header、主题和响应式容器，内容包括：

1. 姓名、角色、头像、个人简介和所属成员类别。
2. 技能标签与已有技能深度条。
3. 由技术方向分类器得到的方向标签。
4. 参与项目及本人角色，使用现有项目链接回退逻辑。
5. 直接协作者，以及每人的共同项目、共同技术方向。
6. 分享和联系区：复制链接、复制邀约、公开联系链接。
7. 返回团队目录入口。

现有 `MemberTechDetail` 中可复用的内容拆为独立 `MemberProfileContent`，供档案页使用。首版成员卡片不再打开弹窗；不再使用的弹窗入口随之移除。技术方向分类器、技能条、项目职责卡等内容不得复制成两套独立实现。

未知 `memberId` 显示明确的“未找到成员”页面，提供返回团队页入口，不渲染空白页或任意第一位成员。

### 5.3 协作关系图

协作面板包含项目 / 技术方向切换、具体节点选择器、SVG 图形、图例和等价列表。

- 中心节点：当前选中的项目或技术方向。
- 周围节点：与中心节点直接关联的成员，边只表示“参与该项目”或“自述标签归入该方向”。
- 只列出至少关联两位成员的项目或方向，单人关系不形成“协作网络”。
- 默认焦点为项目模式下按现有项目数据顺序排列的第一个有效项目；无有效项目则切换到有效技术方向，两者皆无时显示说明。
- 图最多展示 12 位成员，按成员稳定排序取前 12 位；列表始终展示全部关联成员，并显示图形未展示的人数。不得把前 12 位描述为“最佳协作者”。
- 图形节点与列表均可点击打开档案。SVG 有可读标题、描述和键盘操作入口；同时提供无需理解图形即可使用的列表。
- 不使用力学模拟或自动扩散布局；采用确定性的中心—环形布局，避免加载跳动和过度动画。
- 开启减少动态效果偏好时禁用非必要过渡。移动端与减少动态效果不隐藏任何功能或关系信息。

## 6. 数据与计算规则

### 6.1 唯一成员标识

为 `TeamMember` 增加必填的 `id`，每位公开成员使用人工指定、稳定、URL 安全的 ASCII 标识。路由为 `/team/member/${encodeURIComponent(id)}`，不使用姓名作为唯一键。

要求：

- 成员 `id` 全站唯一；开发模式与单元测试校验重复标识并输出姓名，测试失败时不得视为可交付。
- 成员常量和各语言成员数组中的同一位成员必须使用相同 `id`；中文姓名、角色、简介、标签和项目角色继续使用当前语言版本，`id`、项目 `id`、关系计算键不可翻译。
- 同名记录分别保留唯一 `id`，并在档案中展示所属类别；不在本轮自动合并。
- 以同一人为主的身份合并需要维护者确认，另立小范围数据修正，不在关系计算中隐式处理。
- 原有姓名查找入口全部改为按 `id` 查找；React 列表 key 同步使用 `id`。

### 6.2 统一数据模型

新增成员数据组装层，输出 `MemberRecord`：

```ts
type MemberGroup = 'maintainers' | 'developers' | 'designers' | 'contributors'

interface MemberRecord extends TeamMember {
  id: string
  group: MemberGroup
  profilePath: string
  directions: string[]
}
```

输入为四组成员数组和当前语言的成员展示数据。`src/lib/i18n/constants/team.ts` 是成员身份、项目关系、链接和头像的不可译数据源；各语言成员数组只覆盖展示文案，并携带匹配用的 `id`。组装层按 `id` 对齐，而不是依赖中英文数组顺序猜测身份。某位成员缺少对应语言文案时回退到成员常量，不出现空白姓名，也不把不同 `id` 的记录合并。

### 6.3 技术方向归类

把 `MemberTechDetail` 的技术模块与关键词匹配提取为共享模块，成员详情、目录搜索、关系图与分析均调用它。

- 关键词匹配沿用现有规则：拉丁关键词要求词边界，中文关键词使用子串匹配。
- 输入为成员技能标签；若成员有显式技能深度名称，也纳入同一匹配输入。
- 同义标签可归类到同一方向，但档案仍保留原始标签，不把推导出的方向冒充成员填写的原始技能。
- 分类器不利用角色或简介猜测技能，不通过 AI 模型补全技能。
- 中文与英文方向名称通过 i18n 提供，内部方向 `id` 保持一致。

### 6.4 搜索与关系计算

- 搜索文本标准化为去除首尾空格并转小写；匹配姓名、角色、简介、原始标签、项目名称及技术方向名称。
- 角色筛选、文本搜索和关系筛选同时生效，采用 AND 逻辑。
- 无搜索词时保留原有成员分组及顺序；搜索后按 `id` 稳定去重，不编造相关度分数。
- 项目关系仅来自成员 `projects[].id`。展示项目名时优先使用 `src/data/projects.ts` 的当前项目标题；成员记录中的名称可作为回退。
- 共同项目是两位成员 `projects[].id` 的交集；共同技术方向是 `directions` 的交集。
- 直接协作者 = 与当前成员至少共享一个项目或一个技术方向的成员，不包含本人。
- 协作者先按共同项目数量、再按共同方向数量、最后按稳定成员顺序排序。该排序仅用于展示依据更多的关系，不显示为合作分数。
- 无共同关系时显示“现有公开资料不足以生成关系”，而非“该成员没有协作者”。

### 6.5 分析指标

保留角色分布、提交总数和贡献者排行，新增：

- **技术方向覆盖**：每个方向关联的公开成员数量及占全部公开成员的比例；成员可属于多个方向，各方向占比不可相加为 100%。
- **项目参与分布**：每个公开项目关联的成员数；只统计有成员关系的项目。
- **资料完整度**：分别展示有技能标签、有项目关联、有公开联系方式的成员数及占比，不合并成未经验证的个人评分。

所有数字旁边标明统计口径。Gitee / GitHub 贡献继续展示 `generatedAt`，文案使用“贡献快照”而非“当前活跃”。首页已有团队概览如复用指标，必须调用同一计算模块，避免数字不一致。

## 7. 组件与模块边界

| 模块 | 责任 |
| --- | --- |
| `src/lib/team/tech-modules.ts` | 方向定义、关键词匹配、方向归类；不依赖 React |
| `src/lib/team/members.ts` | 成员身份、语言数据组装、稳定标识校验和档案查找 |
| `src/lib/team/relations.ts` | 搜索、共同项目 / 方向、直接协作者、分析聚合；不操作 DOM |
| `src/components/team/MemberExplorer.tsx` | 搜索、分类、关系筛选状态及目录 / 图布局 |
| `src/components/team/CollaborationGraph.tsx` | 焦点选择、SVG、等价列表和成员点击回调 |
| `src/components/team/MemberProfileContent.tsx` | 个人资料、技能、项目与协作者展示 |
| `src/pages/MemberProfilePage.tsx` | 路由解析、未知成员处理、分享 / 邀约和页面 SEO |
| `src/pages/TeamPage.tsx` | 保留团队页整体结构，接入探索器并移除详情弹窗状态 |

`MemberExplorer` 只保存当前页面的 UI 状态；关系与统计不在组件中重复计算。首版无需新增全局状态或 URL 查询参数，刷新团队页恢复默认筛选；档案 URL 始终可直接访问。

现有 i18n 类型与中英文文案同步扩展，新增界面不硬编码中文或英文。成员原文不做机器翻译，保持当前语言策略。

## 8. 分享、错误与隐私

- 分享链接由当前站点 origin 与档案路径生成，复制后展示可读成功反馈。
- 协作邀约是本地纯文本模板，包含成员姓名、最多三个原始标签、共同项目或方向及档案链接；没有共同依据时省略该句。
- 浏览器剪贴板不可用或拒绝权限时，显示可选择复制的文本框和说明，不将失败报告为成功。
- 图片加载失败沿用 `ImageProxy` 的头像回退，不阻断档案与关系操作。
- 缺失技能、项目或联系方式分别显示明确的资料未填写状态，不用空图表或零贡献代替。
- 所有输出只来自已公开的成员资料，不新增或推测邮箱、电话、位置、在线状态及私人关系。
- 不引入第三方关系图脚本或向外部服务发送成员数据。

## 9. 验证与验收

### 9.1 自动验证

运行 `pnpm test`、`pnpm lint` 与 `pnpm build`。为纯计算函数补充聚焦测试，覆盖：

- 拉丁词边界与中文标签匹配。
- 同名成员不同 `id` 的独立查找，以及重复 `id` 校验。
- 中英文文案切换时身份与项目关系不变。
- 搜索、类别和关系筛选组合。
- 共同项目、共同方向、本人排除和稳定排序。
- 图形 12 人上限与完整列表不丢失成员。
- 空标签、空项目和未知档案标识。

项目当前没有测试运行器。本次只为纯数据与关系函数引入 Vitest 和最小测试配置，新增 `test` 脚本；不引入浏览器端到端测试框架，也不为既有无关模块补测试。

### 9.2 页面验证

至少验证以下场景：

1. 桌面端打开团队页，搜索“嵌入式”，切换角色并清除筛选。
2. 选择项目或技术方向，图、列表和成员目录结果一致。
3. 点击卡片与图中节点进入同一稳定档案 URL，刷新后仍能打开。
4. 同名成员链接不会串档；未知 `memberId` 有可用回退。
5. 档案展示已有技能、项目和联系入口；缺失字段有诚实空状态。
6. 复制链接和邀约成功，拒绝剪贴板权限时有手动复制回退，未自动发送消息。
7. 375px 移动视口下无横向溢出，关系信息以列表可用；桌面图形不遮挡目录。
8. 键盘可完成搜索、筛选、打开档案和返回；减少动态效果偏好有效。
9. 中英文切换后界面文案、档案标题和分析说明一致。
10. 首页团队统计与团队页对同一指标采用相同口径。

## 10. 实施顺序与交付边界

1. 建立稳定成员标识、共享技术分类器和纯关系计算，并补测试。
2. 抽离档案内容组件，新增档案路由及未知成员状态。
3. 接入团队页搜索、目录、关系图与移动端列表。
4. 补充分析指标、i18n 和分享 / 联系交互。
5. 运行自动检查与桌面 / 移动端页面验证，记录未能验证的边界。

本次交付不包含真实成员互动后台或成员自行编辑档案。后续只有在有明确内容维护流程、隐私授权和真实协作需求时，才单独设计这些能力。
